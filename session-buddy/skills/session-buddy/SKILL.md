# Session Buddy：每个对话一个文件夹

目标：让工作区始终适合人类阅读——根目录基本只有项目自身的文件和一个 `buddy/` 文件夹，`buddy/` 下每段对话一个文件夹，像一本按日期编排的工作日志。

## 会话文件夹

当本对话**第一次**要为用户创建文件交付物时，建立（或复用）本对话的会话文件夹：

```
buddy/<YYYY-MM-DD>-<主题>/
```

- `<主题>`：2~6 个词概括本次任务，用用户的语言（中文即可），去掉空格与文件系统不安全字符（`\ / : * ? " < > |`）。例如 `buddy/2026-10-25-季度销售报告/`。
- 整个对话复用同一个文件夹；主题发生大的转变时，另开一个新的日期文件夹。
- 同日同名冲突时加序号：`-报告-2`、`-报告-3`。
- 若 `buddy/` 下已有既成的命名习惯，沿用它。
- 纯问答、或只改既有代码而不产生新文件的对话，**不需要**建文件夹。

## 什么放进来，什么不放

**放进来**：为本任务新生成的交付物——报告、文档、生成的 HTML、数据导出、一次性脚本、图表、下载的数据等。文件多时按 `报告/`、`数据/`、`脚本/` 分子文件夹。

**不放进来的**：

- 对既有项目源码/配置的修改——留在原处；
- 用户明确指定了位置的文件——用户说了算，照做；
- ZCode 在聊天里内联渲染的交互页面——它们有自己的专门目录，不要挪动；
- 用户已有的任何文件——未经用户要求绝不移动或重组。

拿不准归属的新文件一律放会话文件夹（宁可多收，不让根目录变乱）。

## 每个文件夹的 README.md

创建会话文件夹时同步创建 README.md，任务收尾时更新，用用户的语言写：

```markdown
# <任务名>

> 日期：YYYY-MM-DD

## 这次做了什么
- （2~5 条平实的人话总结，写给没有盯着屏幕看过程的人）

## 文件清单
| 文件 | 说明 | 怎么打开 |
|---|---|---|
| report.md | 季度销售分析报告 | 编辑器阅读 |
| chart.png | 销售趋势图 | 图片查看器 |
```

## buddy/INDEX.md 总索引

`buddy/INDEX.md` 是所有会话文件夹的目录，新条目放最上面：

```markdown
# AI 工作区索引

每段对话一个文件夹，本文件由 Session Buddy 维护。

| 日期 | 文件夹 | 一句话说明 | 主要产出 |
|---|---|---|---|
| 2026-10-25 | [季度销售报告](2026-10-25-季度销售报告/) | 分析 Q3 销售数据并出报告 | report.md、chart.png |
```

每次创建或更新会话文件夹后同步更新；已存在的 INDEX 合并而非覆盖。

## 收尾检查

- 任务结束前确认：工作区根目录没有本对话产生的散落文件；会话文件夹的 README 和 INDEX 都已更新。
- 若工作区是 git 仓库，可以建议用户把 `buddy/` 加进 .gitignore（先问，不要自作主张）。
